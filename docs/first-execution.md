# Historical milestone: first ADL and UART execution

This page records the initial **27 October 2026** CPU/UART milestone. Its
original omissions are historical. Use [Getting started](getting-started.md)
and [Status](status.md) for current builds and capabilities.

The milestone used QEMU v11.1.2, branch `ez80f91-dev`, CPU `ez80f91`, target
`ez80-softmmu` and machine `ez80f91-minimal`.

## Result and reproduction

`examples/hello_uart0.bin` is a 107-byte raw ROM generated by Python. It switches
from reset to ADL, sets SPL, initializes UART0, executes CALL/RET and PUSH/POP,
polls status and prints exactly `Hello eZ80F91\r\n`, then HALTs. The accompanying
assembly is a readable equivalent, not the source assembled by ZDS.
The complete current implementation remains in `patches/0001-ez80f91-minimal.patch`;
`qemu/` is ignored.

```sh
git clone --depth 1 --branch v11.1.2 https://gitlab.com/qemu-project/qemu.git qemu
sh scripts/apply-qemu-patches.sh
mkdir -p build/ez80
cd build/ez80
../../qemu/configure --target-list=ez80-softmmu --disable-docs --disable-werror --without-default-features --enable-tcg --enable-system --disable-tools
ninja -j8 qemu-system-ez80
cd ../..
python3 tests/test_smoke.py build/ez80/qemu-system-ez80
python3 tests/test_cpu_uart.py build/ez80/qemu-system-ez80
build/ez80/qemu-system-ez80 -M ez80f91-minimal -bios examples/hello_uart0.bin -display none -monitor none -serial mon:stdio
```

**Ctrl+A, X** exits `-serial mon:stdio`; HALT alone does not exit QEMU.
Alternatively use `-serial file:/tmp/uart0.txt -monitor stdio`, then `info registers`
and `quit`. Receive tests require a local Unix socket.

```sh
python3 examples/make_hello_uart0.py /tmp/hello_uart0.bin
```

The historical executable was `/tmp/qemuez80f91-build-baseline/qemu-system-ez80`;
it is not a portable dependency. Use your own `build/ez80/` executable.

## Initial CPU subset

| Area | Initial implementation |
| --- | --- |
| Modes | SIS/SIL/LIS/LIL, JP transitions and mixed CALL/RET |
| Registers | Immediate/pair/index loads, register transfers, EX DE,HL |
| Memory | HL and absolute byte/pair loads/stores |
| Stack | BC/DE/HL/AF/IX/IY PUSH/POP, SPS/SPL, SP from HL/IX/IY |
| Control | Direct/register JP, JR and NZ/Z/NC/C conditions, CALL/RET |
| Other | Pair/index INC/DEC, NOP/HALT/DI, immediate AND/OR/XOR/CP |
| I/O | IN0/OUT0, LD MB,A / LD A,MB, STMIX/RSMIX |

Undefined upper bytes of short multibyte writes are deterministically cleared;
individual byte writes preserve other bytes. Ordinary data prefixes do not
persistently change ADL. LD MB,A is a NOP in Z80 mode. Mixed CALL/RET handling
requires MADL=1; RET.S is rejected. Frames follow UM0077 pp.115–116, 292–293.
Current illegal encodings raise hardware TRAP, rather than the initial fatal
diagnostic. [Extended instructions](extended-opcodes.md) describes later coverage.

One decoded instruction produces a TCG helper call per block. Near 16/24-bit
address ends, the same decoder runs through a helper to handle wrapping without
false page dependencies. I/O boundaries support `-icount shift=0`. There is no
cycle-accuracy claim or refresh-cycle simulation during HALT.

## Initial memory and UART

Reset mapping is flash 000000h–03FFFFh, EMAC RAM FFC000h–FFDFFFh and general RAM
FFE000h–FFFFFFh. Later models add remapping, programmable flash and external banks.

UART C0h–C7h includes DLAB, divisor storage, scratch and functional transmit/receive.
RBR read clears DR. IN0 updates documented flags while preserving carry.
Port-D mode 7 requires DDR=1, ALT1=0, ALT2=1 at A3h–A5h; PD0 is TX, PD1 RX.
CLK_PPD1 (DBh) bit 0 gates UART0 and bit 7 gates port D. References: PS0192
pp.47, 50–51, 182–194.

The initial model used immediate TX and one RX byte, with no FIFO/IRQ/loopback.
Those omissions are superseded by [current UART behavior](flash-uart.md).

## Milestone checks and follow-up

Tests covered reset/HALT, ROM bounds, register widths/prefixes, index stacks,
MBASE/SPS/SPL, CALL/RET frames, exact byte layouts, 64-KiB and 24-bit wrapping,
mode-changing JP, UART output, DLAB/pin/clock gating, socket receive and patch
application to a clean base. Checkpatch had no errors apart from the advisory
request for a future maintainer entry. Migration remains disabled.

Subsequent work added [C startup](freertos-boot.md), [vectors/timers](timer0-interrupts.md),
[debugger integration](zds-ethernet.md), [preemptive tasks](freertos-tasks.md),
[blocking/rollover](freertos-blocking.md), [board/PLL startup](board-startup.md)
and [CamelForth](camelf91.md). These are separate evidence, not claims made by
the initial hello-ROM test.

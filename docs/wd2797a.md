# WD2797A disk controller

```sh
qemuez80f91 --kit --run --wd2797a 0x1000 --dev '/path/to/disks'
```

The directory contains uncompressed `A.img`, `B.img`, …, `P.img`, or plain
filenames `A`, `B`, …; `.img` takes precedence. CP/M currently uses A–D and I/J.
IBM-3740 images have 256256 bytes (77 tracks × 26 sectors × 128 bytes), and
4mb-hd images have 4194304 bytes (1024 tracks × 32 sectors × 128 bytes).
Missing drives remain absent. Modified images are saved at their original raw
length on orderly exit. Read-only files expose write protection.

No CS3 disk RAM or memory bank is required. The launcher attaches `cs3=none`;
the CP/M task disables CS3 and transfers sectors through the Data Register into
its existing DMA buffer. LED registers and application RAM retain their mappings.

Without `--dev`, `ez80f91_disks.<debugport>` is used. Existing individual files
are preserved. On first use the previous combined `ez80f91_cs3.<debugport>` is
split into individual images; otherwise bundled disk templates are copied.
The default controller base is 0x1000. `--devport` remains a CLI alias for
`--wd2797a`. The controller requires eight consecutive external ports, with a
base in 0x100–0xFFF8 outside 0xFEF9–0xFF4B (disk discovery and hostname
configuration reserve 0xFF00–0xFF4B).

## DHCP hostname

The launcher defaults to `ez80<debugport>` (for example `ez804040`). Override
it with `--hostname labor-ez80`. Names are single host labels of 1–63 ASCII
letters/digits with optional interior hyphens. The updated FreeRTOS hostname
hook uses this setting for DHCP option 12; older firmware must be rebuilt
and loaded once. Firmware running on physical hardware retains its `ez80`
fallback when the virtual board descriptor is absent.

The read-only virtual board descriptor is independent of the disk controller:
I/O FF08–FF0B contains `HOST`; FF0C–FF4B contains the NUL-terminated name,
padded to 64 bytes. It survives guest reset. Direct QEMU users can set
`-M ez80f91-minimal,hostname=labor-ez80`; the default uses `--dbgport`
(or `ez800` when no debug port is specified).

## Register map

The first four registers follow the
[Western Digital WD279X-02 data sheet](https://www.onasticksoftware.co.uk/dragon/wd2797.pdf).
The remaining registers represent the virtual board around the controller.

| Offset | Read | Write |
| --- | --- | --- |
| +0 | Status; acknowledges INTRQ | Command |
| +1 | Track low byte | Track low byte |
| +2 | Sector, one-based | Sector, one-based |
| +3 | Data | Data / seek target |
| +4 | Board control latch | Bits 0–3: A=0…P=15; bit 4: side; bit 5: MFM |
| +5 | Bit 0 DRQ, bit 1 INTRQ, bit 7 READY | Reserved |
| +6 | Track high byte | Track high byte: extension for the 1024-track I/J images |
| +7 | 97h identifier | Reserved |

The fixed I/O discovery block at FF00h contains `WD97`, controller base low/high
bytes, protocol version 1 and feature byte 1 (extended tracks). Firmware reads
it, so changing `--wd2797a` does not require rebuilding. These discovery,
drive-select and high-track registers are emulator board extensions, not native
WD2797A registers. Only side zero exists in the supported raw geometries.

## Commands and transfer behavior

Implemented: Restore, Seek, Step/Step In/Step Out with optional track updates,
single/multiple Read Sector and Write Sector, Read Address with synthesized
CRC16, Read Track, Write Track and Force Interrupt. Busy/DRQ remain set while a
data transfer is pending; each Data Register access transfers one byte.
Completion asserts INTRQ, acknowledged by reading Status. Signals are polled
through the board registers; no CPU IRQ/DMA channel is wired automatically.

Sector writes commit only after all 128 bytes arrive. Force Interrupt, reset,
or a drive change discards an incomplete write. Multiple-sector commands stop
with Record Not Found after the last sector of the current track. Restore/Seek
and transfer setup are synchronous; DRQ byte deadlines and Lost Data timing
are not cycle accurate. Index pulses use a synthetic 200-ms revolution;
Force Interrupt supports immediate, ready-transition and index conditions.

Read Track synthesizes an FM/MFM gap/ID/data/CRC stream of 6250/12500 bytes.
Write Track recognizes F5/F6 sync tokens and F7 CRC generation. It validates a
complete track of the configured 128-byte sectors before changing the raw image.
Unsupported/custom IDs, sector sizes or missing sectors return Record Not Found;
bad CRCs return CRC Error. Raw images do not retain flux, custom gap layouts,
deleted-data markers or deliberately bad CRCs. The 4mb-hd geometry and high-track
extension are explicitly beyond an original floppy drive/WD2797A arrangement.

Direct QEMU invocation:

```sh
qemu-system-ez80 -M ez80f91-minimal,cs3=none,wd2797a=0x1000,dev-dir=/path/to/disks
```
